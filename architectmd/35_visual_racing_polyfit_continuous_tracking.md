# ARCH_TITLE: visual_racing_polyfit_continuous_tracking

## 1. システム概要と決定された採用技術

### システム概要
本設計は、自動運転AI（ビジュアルレーシングAI）の軌道追従安定性を極限まで高めるための改修である。
カーブ走行時や画面奥にコース外の影やノイズが存在する場合にステアリングがブレる現象を解消するため、路面重心の抽出手法を刷新する。「連続トラッキング方式」と「最大ブロック抽出方式」を組み合わせることで、足元（確実な路面）から遠方にかけて探索範囲を連続的に絞り込み、純粋なコース路面だけを確実になぞる堅牢な軌道認識（4点 Polyfit）を実現する。

### 決定された採用技術
| 項目 | 採用技術・手法 |
|------|--------------|
| スキャンライン設定（計5本） | カーブ検知用(0.55) 1本、軌道追従用(0.90, 0.80, 0.70, 0.60) 4本 |
| トラッキング探索範囲 (ROI) | 1つ下のスキャンラインで検出した路面中心を基準に「左右±150px」に探索領域を制限。 |
| 最大ブロック抽出 | 指定された探索領域（ROI）内の黒色ピクセルにおいて、最も長く連続している塊（最大ブロック）の中心を「真の路面」として採用する。 |
| カーブ検知・緊急停止 (維持) | 0.55ラインの重心ズレ(15%超)による減速判定、および画面下部の緑色(芝生)面積割合による緊急停止は維持。 |
| 軌道追従制御 (維持) | 取得した4点を用いた `numpy.polyfit` 2次関数近似と、そこから逆算した目標点 `target_x` によるPID制御。 |

## 3. 各ファイルの役割と必要な実装仕様

### 3-1. `course_lap_node.py`
ビジュアルサーボ制御におけるスキャンライン定数を更新し、画像処理コールバック内の重心算出ロジックを「連続トラッキング＋最大ブロック抽出」ベースに書き換える。

*   **制御パラメータ・定数の変更・追加**
    *   **軌道追従（Polyfit 4ライン）用のY座標比率**
        *   `SCAN_Y_BOTTOM_STEER_RATIO = 0.90` （維持: 足元）
        *   `SCAN_Y_NEAR_STEER_RATIO = 0.80` （旧 0.75 から変更）
        *   `SCAN_Y_MID_STEER_RATIO = 0.70` （旧 0.65 から変更）
        *   `SCAN_Y_FAR_STEER_RATIO = 0.60` （旧 0.57 から変更）
    *   **連続トラッキング用定数**
        *   `TRACKING_ROI_WIDTH = 150` （新規追加: 基準点からの左右探索範囲ピクセル数）

*   **最大ブロック抽出ロジックの実装（共通処理）**
    *   入力された1行の2値化マスク（行配列）と探索範囲 `[start_x, end_x]` から、「値が非ゼロ（黒色路面）である最も長い連続区間」を探す。
    *   その最長連続区間の中央インデックスを算出して返す処理（関数化を推奨）を実装する。
    *   ※範囲は `0` 以上 `width - 1` 以下にクリップする（画面外参照を防ぐため）。

*   **連続トラッキングロジック（Image Callback内）**
    以下の手順で下から上へと探索を連鎖させる。
    1.  **Bottom (0.90) の算出:**
        *   探索範囲: `[0, width - 1]` （画面全幅）
        *   処理: 画面全幅から最大ブロックを抽出し、中心を `center_bottom` とする。
    2.  **Near (0.80) の算出:**
        *   探索範囲: `[center_bottom - 150, center_bottom + 150]`
        *   処理: 上記ROI内で最大ブロックを抽出し、中心を `center_near` とする。
    3.  **Mid (0.70) の算出:**
        *   探索範囲: `[center_near - 150, center_near + 150]`
        *   処理: 上記ROI内で最大ブロックを抽出し、中心を `center_mid` とする。
    4.  **Far (0.60) の算出:**
        *   探索範囲: `[center_mid - 150, center_mid + 150]`
        *   処理: 上記ROI内で最大ブロックを抽出し、中心を `center_far` とする。

*   **後続処理（変更なし）**
    *   算出された `center_bottom`, `center_near`, `center_mid`, `center_far` の4点のX座標と対応するY座標を用いて `np.polyfit` で2次関数を算出。
    *   基準Y位置（0.625）での `target_x` を逆算し、PID制御でステアリングへ反映させる。

## 4. データ・制御の処理フロー

```text
【Continuous Tracking & Polyfit 制御 フロー（毎フレーム）】

1. [Image Acquisition]
   └─ カメラ画像取得、HSV変換、黒色（路面）抽出用2値化マスク生成。

2. [Curve Detection] 高速カーブ先読みと速度制御
   └─ Y = 0.55 ラインの重心ズレ(15%以上)に基づき PRE_CURVE / STRAIGHT を切り替え、目標速度を設定。

3. [Continuous Tracking] 連続トラッキング & 最大ブロック抽出
   ├─ [Bottom] Y = 0.90 の行全体から最大路面ブロックを探し、中心(center_bottom)を確定。
   ├─ [Near]   Y = 0.80 の行において、center_bottom ±150px の範囲内で最大ブロックを探し中心(center_near)を確定。
   ├─ [Mid]    Y = 0.70 の行において、center_near ±150px の範囲内で最大ブロックを探し中心(center_mid)を確定。
   └─ [Far]    Y = 0.60 の行において、center_mid ±150px の範囲内で最大ブロックを探し中心(center_far)を確定。

4. [Steering Trajectory Calculation] 4点2次関数近似
   ├─ 抽出した4点のY座標とX座標から np.polyfit(Y_array, X_array, 2) を実行し、係数(a,b,c)を取得。
   └─ 基準Y(0.625)を2次関数に代入し、ノイズのない滑らかな軌道上の目標点 target_x を逆算。

5. [Error Calculation & PID]
   ├─ ステアリング誤差: error = (width / 2.0) - target_x
   └─ PID制御により error を角速度コマンド (cmd_vel.angular.z) へ変換。

6. [Command Publish]
   └─ 最新の速度・角速度コマンドをシミュレータへ送信。
```
