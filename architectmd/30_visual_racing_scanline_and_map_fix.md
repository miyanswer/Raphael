# ARCH_TITLE: visual_racing_scanline_and_map_fix

## 1. システム概要と決定された採用技術

### システム概要
本改修は、自動運転AI（ビジュアルレーシングAI）の超軽量化と、シミュレーション環境のモニタリング機能改善を目的とする。
1. **AI制御の超軽量化（スキャンライン方式）**
   画像全体の2次元領域計算を廃止し、指定した高さの「横1行（1次元データ）」のみを抽出するスキャンライン方式を導入する。これにより計算量を激減させ、処理落ちを防ぐとともに応答性を極限まで高める。
   - **近景ライン**: ステアリング（センタリング）制御用。
   - **中景ライン**: カーブ検知（スローイン）制御用。
2. **シミュレータ俯瞰カメラの修正**
   サブウィンドウの画面分割バグ（メイン映像と混ざる現象）を、Panda3Dの描画領域（DisplayRegion）を正しく再設定することで解消する。同時に、ロボット追従型の俯瞰カメラを廃止し、マップ全景のはるか上空に固定して真下を見下ろす「監視マップカメラ」へと仕様を変更する。

### 決定された採用技術
| 項目 | 採用技術・手法 |
|------|--------------|
| 画像処理の超軽量化 | NumPyによる1次元スライス（スキャンライン抽出）、`np.where` を用いた重心（中点）計算 |
| シミュレータ描画 | Panda3D `DisplayRegion` の明示的割り当て、コースAABB（バウンディングボックス）からの中心座標算出 |
| 制御ロジック | 1次元誤差に基づくPIDステアリング制御、1次元の道幅変化に基づく速度状態遷移 |

## 3. 各ファイルの役割と必要な実装仕様

### 3-1. `course_lap_node.py` (AI制御側)
ビジュアルサーボの処理を2次元マスクから1次元スキャンラインへ変更する。

*   **定数の追加**
    *   スキャンラインの高さを決定する定数を追加する。
    *   `SCAN_Y_STEER_RATIO = 0.80` （画面上部から80%の位置。近景・ステアリング用）
    *   `SCAN_Y_CURVE_RATIO = 0.55` （画面上部から55%の位置。中景・カーブ検知用）
*   **スキャンライン画像処理ロジックの実装**
    *   画像全体のHSV変換後、指定した2行だけを取り出す（例: `h_steer = int(height * SCAN_Y_STEER_RATIO)`）。
    *   取得した1行（Vチャネル）に対し、`BLACK_V_MAX` 以下の条件を満たすインデックス（X座標）を `np.where` 等で取得する。
    *   **ステアリング制御（近景）**: 取得した黒色ピクセルの両端X座標から中点 `center_x = (min_x + max_x) / 2.0` を計算し、画像中央 `(width / 2.0)` との誤差（`error`）を算出してPID制御に渡す。
    *   **カーブ検知・速度制御（中景）**: 中景の1行について、黒色ピクセルの幅（`max_x - min_x`）が一定以下に減少した、あるいは中心が大きくズレた場合にカーブ（`PRE_CURVE` 等）と判定。直進時（`SPEED_FAST`）から減速（`SPEED_SLOW`）へ切り替える。
*   **不要コードの削除**
    *   `cv2.moments` による面積・重心計算、および `upper_mask` `lower_mask` 等の2次元画像分割処理を全て削除する。

### 3-2. `simulation/visualizer.py` & `simulation_base/visualizer.py` (シミュレータ側)
サブウィンドウの描画領域のバグ修正と、マップ俯瞰カメラの固定化を行う。

*   **サブウィンドウ描画の正常化**
    *   `openWindow(name="Top View Window", requireWindow=True)` でサブウィンドウを生成する。
    *   Panda3Dにおいて、新ウィンドウ生成時にメインカメラの映像が混入しないよう、サブウィンドウの `DisplayRegion` をクリアまたは明示的にサブカメラ専用に設定し直す。
*   **マップ中心の算出とカメラ固定**
    *   初期化時（`__init__` または専用セットアップ関数内）において、`self.course_points`（N×2の座標リスト）から `min_x, max_x, min_y, max_y` を計算し、コース全体の中央座標 `(cx, cy)` を算出する。
    *   サブカメラ（`self.sub_cam`）の位置を `(cx, cy, 150.0)` （コース全体が映る十分な高さ）に設定し、姿勢を `setHpr(0, -90, 0)` （真下見下ろし）に固定する。
*   **追従処理の削除**
    *   毎フレーム呼び出される `update_camera` 内で、もし `sub_cam` の位置をロボットに追従させる処理が残っている場合は完全に削除する。

## 4. データ・制御の処理フロー

改修後のシステムにおける処理フローは以下の通りとなる。

```text
【シミュレータ描画フロー（毎フレーム）】
1. メインウィンドウ: ロボットのオドメトリ(x, y, theta)に基づき、メインカメラ(FPV視点等)をロボットに追従させる。
2. サブウィンドウ: ロボットの動きには一切干渉せず、初期化時に設定された「コース全体の中央上空(Z=150)」から固定で全景をレンダリングする。
   └─ ※DisplayRegionが独立しているため、メイン画面のUIや背景が混ざらない。

【ビジュアルレーシング・スキャンライン処理フロー（毎フレーム）】
1. [Image Callback] 画像の取得とHSV変換（2次元処理はここまで）。
2. [Scanline Extraction] 1次元データの抽出
   ├─ Y = height * 0.80 の横1行を抽出（近景ライン）
   └─ Y = height * 0.55 の横1行を抽出（中景ライン）
3. [Speed Control] 中景ラインによるカーブ検知
   ├─ 中景ラインの黒色ピクセルの幅や中心位置をチェック。
   └─ 道幅が狭まる/大きくズレる＝カーブと判定し cmd_vel.linear.x を SPEED_SLOW に切り替え。
4. [Steering Control] 近景ラインによるセンタリング
   ├─ 近景ラインの黒色ピクセルの両端X座標から道幅の中心（center_x）を特定。
   ├─ error = (画面幅 / 2.0) - center_x を計算。
   └─ PID制御で error を角速度 cmd_vel.angular.z に変換。
5. [Motor Output] コマンド送信
   └─ 機体に対して Publish（計算量が極小なため、超低遅延でキレのある走行を実現）。
```
