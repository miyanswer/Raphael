# ARCH_TITLE: visual_racing_camera_offset_and_steering

## 1. システム概要と決定された採用技術

### システム概要
本設計は、画像ベースで自律走行を行うビジュアルレーシングAIにおける「ステアリング制御の極性反転バグ（逆走・暴走）」の根本解決と、シミュレータ上の「カメラ位置（視点）の物理的なズレ」を修正するための設計図である。

絶対座標（マップ座標系）に依存せず、**「機体の正面（カメラ画像の中心）から見て、目標が左右どちらにズレているか」**というローカルな相対座標系に制御基準を統一する。同時に、シミュレータ側のカメラ視点を機体の中心から「バンパーの先端（機体前方）」へオフセットすることで、物理的に正しいドライバー視点（FPV）によるAI認識・制御ループを確立する。

### 決定された採用技術（既存維持）
| 項目 | 採用技術 |
|------|---------|
| 言語 | Python 3.10+ |
| 3Dシミュレータ | Panda3D |
| 行列演算・三角関数 | `numpy`, `math` |
| ROS 2通信・画像変換 | `rclpy`, `geometry_msgs/Twist`, `sensor_msgs/Image`, `cv_bridge` |
| 画像処理 | `OpenCV` (`cv2`) |

## 3. 各ファイルの役割と必要な実装仕様

### 3-1. `course_lap_node.py` (AI制御側)
取得したカメラ画像を解析し、ステアリング制御量を計算する処理のうち、「③ 軌道追従（黒ROI）と動的オフセット」における目標座標（TargetX）計算後の、**誤差（error）の演算ロジック**を以下のように書き換える。

*   **目標位置 (`TargetX`) の計算**: （※既存維持）
    *   黒路面の重心 `Cx` を算出。
    *   ステートに応じて `Cx + OFFSET_OUT`（右寄り）または `Cx + OFFSET_IN`（左寄り）を `TargetX` とする。
*   **【★修正】機体正面（画面中心）を基準としたPID誤差（`error`）の計算**:
    *   画面の横幅を `IMAGE_WIDTH`（想定640px）としたとき、機体の真正面は `IMAGE_WIDTH / 2`（320px）となる。
    *   誤差算出式を以下に変更する。
        ```python
        # 画像の中心座標 (機体の正面)
        center_x = IMAGE_WIDTH / 2.0 
        
        # 正面座標と目標座標のズレを誤差とする
        error = center_x - TargetX
        ```
    *   **理由**: 目標(`TargetX`)が画面中心より右側にある場合（例：TargetX = 400）、`320 - 400 = -80`（マイナス）となる。ROS 2の `Twist.angular.z` において「マイナス」は**右旋回**を意味するため、機体が正しく目標へ向かってステアリングを切る。
*   **角速度のパブリッシュ**: （※既存維持）
    *   算出した `error` を用いてPID演算を行い、`/cmd_vel` に Publish する。

### 3-2. `visualizer.py` (シミュレータ側)
シミュレータの描画更新時にカメラ位置を決定する `update_camera(self, robot_x, robot_y, robot_theta)` メソッドにおいて、カメラを機体中心から前方（バンパー位置）へオフセットする。

*   **【★修正】カメラ位置（X, Y）の前方オフセット計算**:
    *   既存の `robot_x`, `robot_y` をそのままカメラ位置にするのではなく、ロボットの向いている角度 `robot_theta` を利用して `0.4` メートル前方にズラす。
    *   `numpy` (`np`) または `math` を用いて以下のように計算する。
        ```python
        cam_offset = 0.4
        cam_x = robot_x + (cam_offset * np.cos(robot_theta))
        cam_y = robot_y + (cam_offset * np.sin(robot_theta))
        ```
    *   算出された `cam_x`, `cam_y` と既存のカメラ高さ（Z座標）を用いて、Panda3Dのカメラノード（`base.camera.setPos`）を更新する。

## 4. データ・制御の処理フロー

カメラ物理位置の適正化と、画像中心を基準とした直感的なステアリングロジックにより、物理世界（シミュレータ）と認識世界（AI）の整合性が完全に取れる。

```text
【毎フレームのシミュレーション＆制御サイクル】

1. [Simulator] 機体の状態更新とカメラ視点配置
   ├─ ロボットの中心(x, y)と角度(theta)を取得
   └─ theta方向に0.4m進めたバンパー先端(cam_x, cam_y)にカメラをセット

2. [Simulator] FPV画像の配信
   └─ 正確な「ドライバー視点」の画像を /camera/image_raw に Publish

3. [AI Node] 画像受信と目標決定
   ├─ 画像を受信し、黒路面の重心(Cx)を特定
   └─ ステートに応じたオフセットを加味し、目標ピクセル(TargetX)を決定

4. [AI Node] 画面中心（機体正面）を基準にしたステアリング演算
   ├─ TargetX が中心(320)より右側(>320)の場合
   │  └─ error = 320 - TargetX (負の値) ──► angular.z = 負の値 (右旋回コマンド)
   │
   ├─ TargetX が中心(320)より左側(<320)の場合
   │  └─ error = 320 - TargetX (正の値) ──► angular.z = 正の値 (左旋回コマンド)
   │
   └─ 算出された /cmd_vel を Publish して機体を制御する
```
